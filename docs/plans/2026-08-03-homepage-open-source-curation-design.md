# 首页开源贡献精选设计

## 已确认目标

- 首页只承担代表作展示，不把所有合并 PR 塞进三幕项目舞台。
- 项目页的“开源贡献”区继续作为完整、可核验的永久档案。
- 当前两项外部上游合并（Mastra #20312、OpenHands #16168）都应出现在首页。

## 实现边界

首页既有设计规范要求固定的三幕滚动舞台，因此保留一个“公开边界审查”场景，另外两个场景由真实的开源代表作占据。开源贡献数据只在 `src/data/open-source.ts` 维护；`featured` 字段决定它是否进入首页，首页最多取两项，避免详情与首页文案出现两份事实源。

每个首页开源场景统一链接到 `/projects/#open-source-contributions`，入口文案为“查看全部开源贡献”。项目页仍渲染 `openSourceContributions` 全量数据，并按数据中的时间顺序展示所有已被外部维护者合并的贡献。

## 后续维护规则

1. 新合并 PR 总是先写入完整档案。
2. 只有技术深度、上游影响力、验证证据和题材差异足够强的项目才标记为 `featured`。
3. 首页同时最多保留两项开源代表作；新增代表作时替换较弱的一项，不扩展第四幕。
4. 开放 PR、个人仓库合并和被上游替代的补丁不进入成果展示。

## 验证

- 首页三幕顺序正确，第二幕显示 Mastra，第三幕显示 OpenHands。
- 两个入口都跳转到项目页完整开源贡献区。
- 项目页同时显示全部合并记录。
- 桌面 sticky 动效、移动端静态顺序和 reduced-motion 回退均保持可读。
- `npm run lint` 与 `npm run build` 通过，并在桌面与移动视口完成浏览器检查。
